# M3: propositions and user corrections

Create a task with `atlas tasks make --kind gen_propositions --node <node_id>`.
The task includes the node subgraph, source documents, existing propositions,
and the correction journal. Submit and merge through the existing task commands.
Task identity includes the snapshot version, so changed evidence or corrections
produce a new task while an unchanged snapshot is deduplicated.

Each output proposition needs two distinct source-checked support pointers.
Known counter evidence must be retained. `UPDATE` can revise confidence;
`SUPERSEDE` requires `supersedes` (the old ID), a new `prop_id`, and `valid_from`.
The old proposition retains its evidence and receives `valid_to` and
`superseded_by`. All operations are transactional and audited.

`atlas profile list` prints JSON. Use
`atlas profile correct <prop_id> --verdict wrong|right|amend --note "..."`
to append to `<data_dir>/corrections.jsonl`. `wrong` rejects and suppresses;
`right` confirms and explicitly lifts suppression; `amend` requires a nonempty
note and preserves it as `user_note`, without silently rewriting the claim.
Journal rows have `correction_id`, `prop_id`, `verdict`, `note`, and `observed_at`.
Rows replay in file order and are append-only. Profile reads, task packing, and
merges replay corrections, including before an idempotent merge returns.

Agent updates cannot overwrite suppression or user confirmation. A new ID with
the same normalized text and subject set is also blocked when suppressed.
This is deterministic matching, not semantic paraphrase detection. Rejected
proposals produce audited NOOPs at merge. Sensitive source/node flags propagate.
Confidence values come from validated agent output; no scoring model is invented.
